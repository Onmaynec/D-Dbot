## 🤝 Что нового в 4.6

Версия **4.6.0** добавляет полевую поддержку во время многопользовательского боя.

- команда `/support` показывает раненых и потерявших сознание героев;
- любой живой участник может потратить свой ход на лечение союзника;
- используются обычные и большие зелья из общего инвентаря партии;
- лечебное зелье может вернуть героя с `0 HP` обратно в бой;
- интерфейс показывает запас зелий, HP и состояние хода каждого участника;
- если лечение стало последним действием партии, сразу начинается общая фаза врагов;
- повторный или параллельный клик не списывает дополнительное зелье;
- инвентарь, HP, список ходов и состояние боя обновляются одной SQLite-транзакцией;
- история помощи сохраняется в `party_support_history`.

```text
партийный бой → /support → выбрать союзника → выбрать зелье
лечение тратит ход → последний ход запускает фазу врагов
```

## 👥 Партийный бой 4.5

Каждый живой участник партии действует своим героем один раз за раунд.

- физическая атака использует Силу, уровень и бонус мастерства конкретного героя;
- заклинание использует Мудрость и уровень конкретного героя;
- враги начинают общую фазу только после ходов всех живых участников;
- каждый враг выбирает цель среди героев, оставшихся в сознании;
- экран боя показывает, кто уже сходил, кто ожидает ход и кто потерял сознание;
- HP, XP, список сделавших ход игроков и состояние врагов сохраняются атомарно;
- одиночный режим автоматически сохраняется для чатов без участников партии.

```text
Партия → Вступить в партию
Бой → каждый игрок атакует, колдует или использует /support
последний ход партии → общая фаза врагов → новый раунд
```

### Связь с тактическими предметами

- **Свиток щита** защищает всю партию во время фазы врагов;
- **Перо феникса** спасает первого героя, чьи HP опустились до нуля;
- команда `/tactics` работает и в многопользовательском бою.

## 🎒 Тактические предметы 4.4

Команда `/tactics` открывается во время активного боя.

- **Свиток щита** даёт `+2 КД` на две фазы врагов;
- **Перо феникса** один раз возвращает героя с половиной максимального HP;
- активные эффекты сохраняются в combat-state;
- предмет и состояние боя обновляются одной SQLite-транзакцией;
- операции записываются в `combat_item_history`.

```text
/forge → создать Свиток щита или Перо феникса
бой → /tactics → активировать предмет → продолжить сражение
```

## ⚒️ Кузница 4.3

Команда `/forge` создаёт расходники и перерабатывает лишнюю добычу в золото.

| Результат | Ингредиенты | Цена |
|---|---|---:|
| Большое зелье лечения | 2 × Зелье лечения | 15 зм. |
| Свиток щита | Свиток удачи + Серебряные стрелы | 20 зм. |
| Перо феникса | 2 × Жетон судьбы + Большое зелье лечения | 80 зм. |

Крафт, разбор предмета и изменение общей казны выполняются атомарно. История хранится в `forge_history`.

## 🎁 Ежедневные награды 4.2

Команда `/daily` выдаёт одну награду на чат за календарный день UTC.

- золото поступает в общую казну;
- каждый третий последовательный день выдаётся предмет;
- каждый седьмой — эпический Жетон судьбы и дополнительное золото;
- пропуск дня сбрасывает серию;
- повторные запросы не выдают награду дважды.

## 🛡️ Надёжность 4.1

При каждом запуске бот создаёт консистентную резервную копию SQLite через штатный Backup API.

```env
BACKUP_ON_START=true
BACKUP_DIR=data/backups
BACKUP_KEEP=7
```

Команда `/status` показывает версию, размер базы и результат `PRAGMA quick_check`.

## 🚀 Запуск

```bash
git clone https://github.com/Onmaynec/D-Dbot.git
cd D-Dbot
python -m venv .venv
```

Активация окружения:

```bash
# Windows
.venv\Scripts\activate

# Linux / macOS
source .venv/bin/activate
```

Установка:

```bash
pip install -r requirements.txt
```

Создай `.env`:

```env
BOT_TOKEN=токен_от_BotFather
DATABASE_PATH=data/dnd_bot.sqlite3
LOG_LEVEL=INFO
BACKUP_ON_START=true
BACKUP_DIR=data/backups
BACKUP_KEEP=7
```

Запуск:

```bash
python -m app.main
```

После обновления перезапусти бота и отправь `/start`.

## 🐳 Docker

```bash
docker compose up -d --build
```

pip install -r requirements-dev.txt
ruff check . --select E9,F63,F7,F82

CI выполняется на Python 3.11 и 3.12. После успешного CI на `main` release-job:

1. читает версию из `app.__version__`;
2. создаёт тег `v<version>`;
3. создаёт GitHub Release;
4. устанавливает `make_latest: true`.
